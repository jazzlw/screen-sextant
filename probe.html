Diagnostics

EXIF probe / what’s really in the file

The main tool needs one tag: FocalLengthIn35mmFilm. This shows everything the file carries, so a missing focal length can be traced to a cause instead of guessed at.

Four ways in — try each

Each button configures the file input differently, but iOS still offers its own sheet: the choice you make there matters more than the button. In-page camera capture is re-encoded and stripped; Camera-app photos picked from the library are not.

The two variables are whether the camera is opened in-page and whether a concrete MIME type is requested. Running all four says which one matters.

What to compare

  1. Shoot the same scene both ways, so only the path differs.
  2. Check Container first. ISOBMFF/heic means iOS handed over the original HEIC and never transcoded — the parser is JPEG-only, so nothing else matters.
  3. Then Exif APP1. Absent on a JPEG means the metadata was never written or was stripped in the capture path. That is not something this page can work around.
  4. Then look for FocalLengthIn35mmFilm in the Exif sub-IFD. Present but unreadable is a parser bug and my problem; absent is the camera’s choice.
  5. If FocalLength survives but FocalLengthIn35mmFilm doesn’t, say so — the 35mm equivalent can be reconstructed from it plus a per-device crop factor.

Nothing leaves the device. The file is read in the page and never uploaded.
